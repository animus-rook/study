## 4.1 Access Control Models
### 4.1.1 Fundamental Security concepts
- [[CIA Triad]]
    - [[Confidentiality]]
    - [[Integrity]]
    - [[Availability]]
- Access Control
    - ensures info system meets the goals laid out by [[CIA Triad]]
    - Dictates how Subjects
        - Users, devices or processes
    - Interacts with objects
        - networks, servers, databases, apps, files
    - Implemented using [[IAM - Identity and Access Management]]
        - Identification - unique ids
        - Authentication - Proving identity of subjects
        - Authorization - determines and regulates the rights a subject has
        - Accounting - Tracking of authorized usage and unauthorized access
- [[non-repudiation]] - person is unable to deny preforming an action
- Gap analysis - how well an orgs security meets security frameworks
- Zero trust - everything is untrusted
    - Adaptive Identity
        - Identity changes and needs continuous verification
    - Threat Scope Reduction
        - Limits access on a need to know basis
    - Policy Driven Access Control
        - enforces access restrictions based on user identity, device policy and context related to network
    - Control plane and data plane are separated
        - Control Plane 
            - Defines access policies 
            - monitors threats
            - updates policy
        - Data Plane
            - Establishes secure data pathways and enforces access policies
        - Separation enhances flexibility and security 

### 4.1.2 Access Control Facts

- three properties of security are 
	- [[Confidentiality]]
	- [[Integrity]]
	- [[Availability]]
- All together are known as the [[CIA Triad]]
- Some researchers also include [[non-repudiation]] as a property
#### Cybersecurity Framework
- Infosec and cybersecurity can be put into 5 categories based on [[NIST - National Institute of Standards and Technology]] framework 
	- Identify
		- Evaluate risks, threat and vuln, and recommend mitigating controls
	- Protect
		- procure, install, operate and decomiosn devices with thoughts on security for every step
	- Detect
		- ongoing proactive monitoring, ensure controls are effective
	- Respond
		- identify, and contain or get rid of threats to data or systems
	- Recover
		- resilience to restore data and systems as needed
#### [[Gap analysis]]
- identifies where organization security may differ from required or recommended frameworks or regulatory requirements 
#### Access Control
- ensures that all three goals of the [[CIA Triad]] are met
- governs how [[subjects-principals]] interact with [[objects]]
	- [[subjects-principals]] are people devices software, anything that can request and be granted access
	- [[objects]] are resources such as a network, server, database app, etc
- typically implemented as a [[IAM - Identity and Access Management]] composed of 4 main parts
	- [[identification]]
		- unique ID for a user, device or process
	- [[authentication]]
		- proving that [[subjects-principals]] are who they say they are, [[authentication]] factor determines the type of credential a [[subjects-principals]] may use to authenticate
	- [[authorization]]
		- what level of access a [[subjects-principals]] should have for a given resource and enforcing that access
	- [[accounting]]
		- tracking authorized use and alerting when unauthorized use is detected
- Servers and protocols that implement these functions is known as [[AAA - Authentication-authorization and accounting]]
#### [[Zero Trust]]
- Security model that requires all users to be authenticated and authorized regardless of location relative to resource. Fundamental concepts
	- Adaptive Identity 
		- identities are not static and verification must be based on context of what is being accessed
	- Threat scope reduction
		- access is granted on a need to know basis and is limited to only what is needed to complete the task
	- policy driven access control
		- how access controls are used to enforce restrictions based on
			- identity
			- network context
			- device posture
	- [[device posture]] - security status of device, how risky is it and what is its security configurations
- Control and Data plans in [[Zero Trust]] models
- [[control pane]] manage/dictates how users and devices are authorized to access resources
- Data Plane is where the secure session to transmit data is ran

### 4.1.4 Access Control Models
- [[DAC - Discretionary Access Controls]]
	- Least restrictive
	- all resources have owners and owner dictates access
	- lost of admin work needed
- [[Mandatory access controls]]
	- static system 
	- every computer , object is assigned a label
	- every user is assigned an access level
	- all or none
- [[RBAC - role based access control]]
	- Hybrid between [[Mandatory access controls]] and [[DAC - Discretionary Access Controls]] 
	- role in organization dictates what that user has access to
- [[rule based access control]]
	- Used with routers and router access control lists
	- routers use IP and check against rules in ACL
- [[ABAC -Attribute-based access control]] 
	- Flexible controls
	- combines objects attributes
	- if then else format
- [[conditional access]]
	- user or group level 
	- ip address restrictions
### 4.1.5 Access Control Model Facts
- [[DAC - Discretionary Access Controls]]
	- based on owner 
	- every file has an owner and each files access must be configured
	- Most flexible, also weakest and no central configuration
- [[Mandatory access controls]]
	- based on security clearance levels 
	- Object is given a classification level and subjects are granted permission levels
	- can also enforce that while read permissions work for lower levels of access users can only write at their assigned level
- [[RBAC - role based access control]]
	- permissions are defined by tasks that users must perform
		- ex: Developer, secretary, custodian
- [[ABAC -Attribute-based access control]]
	- most fine grained
	- [[subjects-principals]] and [[objects]] get assigned attributes and permission is based on if [[subjects-principals]] has the matching attributes of an [[objects]]
- [[rule based access control]]
	- set by system enforced rules as opposed to set by system users
	- Conditional access is an example
	- User account control windows and sudo in Linux are examples of conditional access
- [[Principal of Least Privilege]]
	- [[subjects-principals]] is given the least amount of access needed to complete the desired task
- [[provisioning]]
	- process of setting up a service according to standard procedure, usually involves the following steps
		- Identity Proofing - verifying the person is who they say they are
		- issuing credentials - user setting password
		- issuing hardware and software assets - giving computer as well as applicable software keys
		- policy awareness - training on appropriate security policies
		- setting proper permissions
- [[deprovisioning]]
	- removing access rights and provisions
- Locations based
	- using some type of [[geolocation]] mechanism
		- IP 
		- Other location services data provided by hardware or agent
- Time based restrictions
	- 4 main types
		- [[time of day restrictions]] authorized login hours
		- duration - how long logged in for
		- impossible travel time/risky login - cant log in in LA then NY a few minutes or hours later
		- temporary - account given security clearence for a limited time

	- selecting technology that meets goals of [[CIA Triad]]

	- Using multiple factors to authenticate a user
		- Something you know - knowledge factor
			- password or  [[PIN - personal identification number]]
		- Something you are
			- biometrics, fingerprints, iris, 
		- Somewhere you are
			- [[geolocation]]
		- Something you can do
			- writing sample/typing test
		- Something you exhibit
			- login times
			- personality/trait
			- access method
		- Someone you know
			- being vouched for 
		- Something you have
			- hardware token
			- authenticator 
				- [[OTP - One Time Password]]
				- [[Smart Cards]]
				- [[Security Key]]
			- [[Soft Authentication token]]
				- token that is not a device per say messages to your phone or email 
		- [[Passwordless]]
			- no longer uses knowledge based factors
				- roaming authenticator, face ip, windows hello
				- secure method or gesture to confirm presence, enter passcode for example
				- registers web application generates a key pair for that web app
				- when needing to login user makese gesture and private key us used to unlock
				- relaying party uses public key to validate private key and authenticate login
