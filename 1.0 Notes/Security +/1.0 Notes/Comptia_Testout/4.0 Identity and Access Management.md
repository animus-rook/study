## 4.1 Access Control Models
### 4.1.1 Fundamental Security concepts
- [[CIA Triad]]
    - [[Confidentiality]]
    - [[Integrity]]
    - [[Availability]]
- Access Control
    - ensures info system meets the goals laid out by [[CIA Triad]]
    - Dictates how Subjects
        - Users, devices or processes
    - Interacts with objects
        - networks, servers, databases, apps, files
    - Implemented using [[IAM - Identity and Access Management]]
        - Identification - unique ids
        - Authentication - Proving identity of subjects
        - Authorization - determines and regulates the rights a subject has
        - Accounting - Tracking of authorized usage and unauthorized access
- [[non-repudiation]] - person is unable to deny preforming an action
- Gap analysis - how well an orgs security meets security frameworks
- Zero trust - everything is untrusted
    - Adaptive Identity
        - Identity changes and needs continuous verification
    - Threat Scope Reduction
        - Limits access on a need to know basis
    - Policy Driven Access Control
        - enforces access restrictions based on user identity, device policy and context related to network
    - Control plane and data plane are separated
        - Control Plane 
            - Defines access policies 
            - monitors threats
            - updates policy
        - Data Plane
            - Establishes secure data pathways and enforces access policies
        - Separation enhances flexibility and security 

### 4.1.2 Access Control Facts

- three properties of security are 
	- [[Confidentiality]]
	- [[Integrity]]
	- [[Availability]]
- All together are known as the [[CIA Triad]]
- Some researchers also include [[non-repudiation]] as a property
#### Cybersecurity Framework
- Infosec and cybersecurity can be put into 5 categories based on [[NIST - National Institute of Standards and Technology]] framework 
	- Identify
		- Evaluate risks, threat and vuln, and recommend mitigating controls
	- Protect
		- procure, install, operate and decomiosn devices with thoughts on security for every step
	- Detect
		- ongoing proactive monitoring, ensure controls are effective
	- Respond
		- identify, and contain or get rid of threats to data or systems
	- Recover
		- resilience to restore data and systems as needed
#### [[Gap analysis]]
- identifies where organization security may differ from required or recommended frameworks or regulatory requirements 
#### Access Control
- ensures that all three goals of the [[CIA Triad]] are met
- governs how [[subjects-principals]] interact with [[objects]]
	- [[subjects-principals]] are people devices software, anything that can request and be granted access
	- [[objects]] are resources such as a network, server, database app, etc
- typically implemented as a [[IAM - Identity and Access Management]] composed of 4 main parts
	- [[identification]]
		- unique ID for a user, device or process
	- [[authentication]]
		- proving that [[subjects-principals]] are who they say they are, [[authentication]] factor determines the type of credential a [[subjects-principals]] may use to authenticate
	- [[authorization]]
		- what level of access a [[subjects-principals]] should have for a given resource and enforcing that access
	- [[accounting]]
		- tracking authorized use and alerting when unauthorized use is detected
- Servers and protocols that implement these functions is known as [[AAA - Authentication-authorization and accounting]]
#### [[Zero Trust]]
- Security model that requires all users to be authenticated and authorized regardless of location relative to resource. Fundamental concepts
	- Adaptive Identity 
		- identities are not static and verification must be based on context of what is being accessed
	- Threat scope reduction
		- access is granted on a need to know basis and is limited to only what is needed to complete the task
	- policy driven access control
		- how access controls are used to enforce restrictions based on
			- identity
			- network context
			- device posture
	- [[device posture]] - security status of device, how risky is it and what is its security configurations
- Control and Data plans in [[Zero Trust]] models
- [[control pane]] manage/dictates how users and devices are authorized to access resources
- Data Plane is where the secure session to transmit data is ran

- Best practices for Access control take look at
	- [[Principal of Least Privilege]]
	- [[Need to know]]
	- [[Separation of Duties]]
	- [[Job Rotation]]
	- [[Defense In depth]]
	- [[(MFA) Multifactor Authentication]]
	- [[Mutual Authentication]]
	- [[time of day restrictions]]
- Practices for employee transitions

| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account Creations | Appropriate access rights should be applied at the get go, using [[Principal of Least Privilege]]                                                                                                 |
| Active Accounts   | ensure changes are made as employee access changes (additions/removals), reevaluate access rights on a regular schedule                                                                           |
| Old Accounts      | when no longer needed:<br>- delete<br>- Lock accounts that will not be used for a while <br>- Delete old data from accounts when safe to do so from a regulatory and reporting standpoint<br><br> |
